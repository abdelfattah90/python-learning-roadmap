01الشرح

Modules و Create Modules: ملف واحد يصبح وحدة قابلة لإعادة الاستخدام

لماذا؟ عندما يكبر البرنامج يصبح وضع كل شيء في ملف واحد صعب القراءة والاختبار وإعادة الاستخدام. الـ module هو ببساطة ملف .py يحتوي تعريفات (functions و constants و classes) يمكن لأي ملف آخر استيرادها، ولكل module namespace خاص به فلا تتصادم أسماؤه مع أسماء غيره.

Create Modules: لا يوجد شيء خاص في الإنشاء؛ احفظ الكود في ملف بامتداد .py. اسم الملف هو اسم الـ module، فاجعله حروفًا صغيرة صالحة كـ identifier مثل shipping (بلا مسافات أو شرطات ولا يبدأ برقم).

القيد المهم: عند أول import يُنفَّذ الملف كاملًا من أعلاه إلى أسفله، لذلك لا تضع على مستوى الملف كودًا يشغّل شيئًا. ضع الاختبار الذاتي داخل الحارس if __name__ == "__main__":. قيمة __name__ تساوي "__main__" عند تشغيل الملف مباشرة، وتساوي اسم الـ module عند استيراده، فلا يعمل الحارس إلا في التشغيل المباشر. المخرج أدناه ناتج python shipping.py.

Import Modules و from ... import: كيف تصل إلى محتوى الوحدة

Import Modules: import shipping يربط اسم الـ module كاملًا، وتصل لمحتوياته بالنقطة مثل shipping.shipping_cost(2). ميزته أن مصدر كل اسم واضح في الكود ولا تتصادم الأسماء.

from ... import: from shipping import shipping_cost يربط الأسماء المطلوبة فقط بملفك فتستعملها مباشرة. الكود أقصر، لكن مصدر الاسم أقل وضوحًا، وإذا وُجد اسم مماثل قبله فإن آخر استيراد يستبدله بصمت. تجنّب from shipping import * لأنه يجلب كل الأسماء العامة دفعة واحدة ويلوّث الـ namespace.

ملاحظة: يستورد Python الـ module مرة واحدة فقط ويخزنه في sys.modules، فتكرار الاستيراد لا يعيد تنفيذ الملف. ويبحث عنه أولًا في مجلد السكربت الجاري تشغيله ثم في بقية مسارات sys.path. لاحظ أن سطر Self-test لم يظهر في المخرج لأن الحارس لم يعمل عند الاستيراد.

Aliases: اسم بديل محلي

الـ alias اسم بديل يُعطى عند الاستيراد: import shipping as ship أو from math import ceil as round_up. نستخدمه لاختصار اسم طويل، أو لحل تصادم بين اسمين متماثلين، أو لتوضيح المعنى. هو يغيّر الاسم في ملفك فقط ولا يغيّر الـ module، وبعد as لا يبقى الاسم الأصلي متاحًا (استخدام shipping بعد import shipping as ship يعطي NameError).

في المثال عرّفنا دالة محلية باسم shipping_cost دون أن تتعارض مع دالة الـ module لأننا نصل إليها عبر ship.

Built-in Modules: مكتبة Python القياسية جاهزة بلا تثبيت

يأتي Python مع modules جاهزة مثل math و statistics و random و datetime و sys. نستوردها بنفس الطريقة تمامًا، فنوفّر كتابة كود جاهز ومُختبَر. (المصطلح هنا يشمل المكتبة القياسية كلها.)

لاكتشاف محتوى أي module استخدم dir(module) لسرد أسمائه، و help(module.name) لعرض توثيق اسم محدد.

الخطأ الشائع: تسمية ملفك باسم module قياسي مثل random.py أو math.py. لأن مجلد السكربت يُبحث فيه أولًا، سيستورد Python ملفك بدل الـ module الأصلي.

02الملخص

  • الـ module هو ملف .py يحتوي تعريفات قابلة لإعادة الاستخدام، ولكل module namespace مستقل.
  • يُنفَّذ الـ module كاملًا عند أول import فقط ثم يُخزَّن في sys.modules؛ استخدم if __name__ == "__main__": لفصل كود التشغيل المباشر عن كود الاستيراد.
  • import module يحافظ على وضوح المصدر عبر module.name، بينما from module import name يختصر الكتابة على حساب وضوح المصدر.
  • تجنّب from module import * لأنه يلوّث الـ namespace ويُخفي من أين جاء كل اسم.
  • as ينشئ alias محليًا لاختصار الأسماء أو حل التصادم، ولا يُبقي الاسم الأصلي متاحًا في ملفك.
  • المكتبة القياسية جاهزة بلا تثبيت، وتكتشفها بـ dir() و help()؛ وتجنّب تسمية ملفاتك بأسمائها مثل random.py.

03أسئلة المقابلات

ما هو الـ module في Python ولماذا نستخدمه؟أساسي

الـ module ملف .py يحتوي تعريفات (functions و constants و classes) يمكن استيرادها من ملفات أخرى. نستخدمه لتقسيم البرنامج إلى أجزاء مفهومة، ولإعادة استخدام الكود بدل نسخه، ولعزل الأسماء داخل namespace مستقل.

متابعة: إذا استوردت الـ module نفسه من خمسة ملفات، فكم مرة يُنفَّذ؟ مرة واحدة فقط، لأن Python يخزنه في sys.modules.

ما الفرق بين import shipping و from shipping import shipping_cost؟أساسي

الأول يربط اسم الـ module فقط فتصل لمحتوياته بالنقطة shipping.shipping_cost()، والثاني يربط اسم الدالة مباشرة في ملفك. الأول أوضح مصدرًا وأقل عرضة للتصادم، والثاني أقصر. وفي الحالتين يُنفَّذ الـ module كاملًا عند الاستيراد.

ماذا يفعل if __name__ == "__main__": ولماذا نستخدمه؟متوسط

__name__ يساوي "__main__" عند تشغيل الملف مباشرة، ويساوي اسم الـ module عند استيراده. فالكود داخل الحارس يعمل في التشغيل المباشر فقط، فنضع فيه الاختبار الذاتي أو التقرير دون أن يظهر أثره عند استيراد الملف من غيره.

متى تستخدم alias، ولماذا يُنصح بتجنب from module import *؟متوسط

نستخدم alias لاختصار اسم طويل أو لحل تصادم بين اسمين متماثلين، مثل from math import ceil as round_up. أما star import فيجلب أسماء كثيرة غير ظاهرة في ملفك، فقد يستبدل أسماء موجودة بصمت ويصعب معه معرفة مصدر أي اسم.

سمّيتُ ملفي random.py وكتبت فيه import random ثم random.randint(1, 6) فظهر AttributeError. ما السبب؟فخ

Python يبحث أولًا في مجلد السكربت، فوجد ملفك random.py واستورده بدل الـ module القياسي، وهو لا يحتوي randint. الحل أن تغيّر اسم ملفك إلى اسم مختلف لا يطابق أي module قياسي.

04المسألة العملية

المسألة: يريد متجر إلكتروني وحدة parcel_pricing.py تحسب تكلفة الشحن: رسم أساسي 30، و12.5 لكل كيلوغرام، مع تقريب الوزن لأعلى إلى أقرب كيلوغرام كامل. المطلوب دالة parcel_cost لطرد واحد ودالة average_cost لمتوسط تكلفة قائمة أوزان، بحيث يمكن استيراد الملف دون أن يطبع شيئًا، ويطبع تقريرًا قصيرًا عند تشغيله مباشرة.

  1. فهم المطلوب

    المدخلات وزن واحد أو قائمة أوزان، والمخرجات تكلفة طرد ومتوسط تكاليف. هناك شرطان: تقريب الوزن لأعلى، وألا يطبع الملف شيئًا عند استيراده.

  2. خطة الحل

    ثوابت للرسوم في أعلى الملف، ثم math.ceil لتقريب الوزن، ثم statistics.mean للمتوسط، وأخيرًا حارس __main__ للتقرير.

  3. الكود الكامل

  4. تفسير القرارات

    استوردنا math كاملًا ليبقى مصدر ceil ظاهرًا، واستخدمنا alias stats اختصارًا لـ statistics لأن الاسم يتكرر. وضعنا الرسوم في constants واحدة ليسهل تغييرها، وغلّفنا التقرير بالحارس حتى يبقى الملف آمنًا للاستيراد.

  5. اختبار سريع

    في ملف آخر بنفس المجلد اكتب from parcel_pricing import parcel_cost ثم print(parcel_cost(0.1)). يجب أن يطبع 42.5 فقط (وزن 0.1 يُقرَّب إلى 1 كغ) ولا يظهر سطرا التقرير، وهذا يثبت أن الحارس يعمل.

  6. تحسين أو بديل

    يمكن جعل الرسوم معاملات افتراضية: def parcel_cost(weight_kg, base_fee=BASE_FEE, rate=RATE_PER_KG) فيسهل اختبار أسعار أخرى دون تعديل الـ module. وإذا كان اسم الدالة طويلًا في ملف التقارير، فاستورده بـ from parcel_pricing import parcel_cost as cost.
