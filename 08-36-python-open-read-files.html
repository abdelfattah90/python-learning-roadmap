01الشرح

open() وFile Modes وFile Objects

البرنامج يعمل في الذاكرة، أما الملفات فتعيش على القرص. الدالة open() هي الجسر بينهما: تطلب من نظام التشغيل فتح الملف وتعيد File Object، وهو مقبض (handle) يحمل الاسم والوضع ومؤشر قراءة داخليًا، وليس محتوى الملف نفسه. الصيغة المعتادة: open(path, mode="r", encoding="utf-8").

الوضع (mode) يحدد ما يُسمح لك بفعله:

  • "r" قراءة، وهو الافتراضي؛ يرفع FileNotFoundError إن لم يوجد الملف.
  • "w" كتابة؛ ينشئ الملف أو يفرّغه فورًا عند الفتح.
  • "a" إضافة في نهاية الملف دون مسح، و"x" إنشاء حصري يفشل إن كان الملف موجودًا.
  • "+" يضيف القراءة والكتابة معًا (مثل "r+")، و"b" وضع ثنائي بدل النصي الافتراضي "t".

نركّز هنا على "r" (الكتابة موضوع لاحق). مرّر encoding="utf-8" دائمًا للملفات النصية، وإلا استُخدم ترميز النظام وقد تفسد الحروف العربية. والمسار النسبي يُحسب من مجلد التشغيل الحالي لا من مكان السكربت، وهذا سبب شائع لـ FileNotFoundError. أمثلة الدرس تفترض وجود هذا الملف بجانب السكربت (ينتهي بسطر جديد):

Close Files وwith Statement

الملف المفتوح يستهلك مورد نظام تشغيل (file descriptor)، وقد تبقى البيانات في buffer ولا تصل للقرص إلا عند الإغلاق، وقد يُقفل الملف عن برامج أخرى. لذلك نغلقه بـ close()، وأي قراءة بعده ترفع ValueError. لكن الإغلاق اليدوي هش: إن وقع استثناء قبل close() فلن يُنفَّذ.

الحل هو with: يضمن إغلاق الملف عند مغادرة الكتلة حتى مع الاستثناءات. القيد: يبقى المتغير موجودًا بعد الكتلة لكن الملف مغلق، فاقرأ ما تحتاجه داخلها.

read() وreadline() وreadlines()

كل قراءة تبدأ من موضع المؤشر الحالي وتحرّكه للأمام:

  • read() تعيد كل ما تبقّى كسلسلة واحدة، وread(n) تعيد n حرفًا فقط.
  • readline() تعيد سطرًا واحدًا بما فيه \n.
  • readlines() تعيد list بكل الأسطر المتبقية.

عند نهاية الملف تعيد read() وreadline() سلسلة فارغة "" دون استثناء، وتعيد readlines() قائمة فارغة. الثلاث تحمّل ما تقرؤه في الذاكرة، فلا تستخدم read() أو readlines() مع ملفات ضخمة.

Read Files Line by Line

الـ File Object نفسه iterator (كما في درس Iterators)، فـ for line in file يقرأ سطرًا واحدًا في كل دورة دون تحميل الملف كله، وهو الخيار الافتراضي للملفات الكبيرة. كل line ينتهي بـ \n وprint تضيف سطرًا آخر فتظهر أسطر فارغة، لذا استخدم rstrip(). ولترقيم الأسطر استخدم enumerate(file, start=1). تنبيه: لا تخلط readline() مع الحلقة على نفس الملف، فالمؤشر واحد وستتداخل القراءتان.

02الملخص

  • open() تعيد File Object (مقبضًا) وليس المحتوى، والوضع الافتراضي "r" للقراءة النصية.
  • الأوضاع: "r" قراءة، "w" يفرّغ الملف عند الفتح، "a" يضيف، "x" ينشئ حصريًا، "+" للقراءة والكتابة، "b" ثنائي.
  • حدّد encoding="utf-8" للملفات النصية، وتذكّر أن المسار النسبي يُحسب من مجلد التشغيل.
  • استخدم with لإغلاق الملف تلقائيًا حتى عند الاستثناءات؛ والقراءة بعد الإغلاق ترفع ValueError.
  • read() نص كامل، readline() سطر واحد، readlines() قائمة أسطر؛ ونهاية الملف تعطي "" أو قائمة فارغة.
  • للملفات الكبيرة مرّ بـ for line in file واحذف \n بـ rstrip().

03أسئلة المقابلات

ماذا تعيد open()، وما وضعها الافتراضي؟أساسي

تعيد File Object وليس نص الملف؛ لقراءة المحتوى تستدعي عليه read() أو readline() أو تمرّ عليه بحلقة. الوضع الافتراضي "rt" أي قراءة نصية، وإن لم يوجد الملف يُرفع FileNotFoundError.

متابعة: لماذا نكتب encoding="utf-8" صراحةً؟ لأن الترميز الافتراضي يختلف بين الأنظمة وقد يفسد النص العربي.

لماذا يُفضَّل with على open() مع close() يدويًا؟أساسي

لأن with يغلق الملف عند مغادرة الكتلة حتى لو وقع استثناء، بينما قد يُتخطّى close() اليدوي فيبقى الملف مفتوحًا ويتسرّب المورد. كما أنه يبيّن بوضوح أين ينتهي استخدام الملف.

ما الفرق بين read() وreadline() وreadlines()؟متوسط

read() تعيد المتبقي كنص واحد، وreadline() سطرًا واحدًا بما فيه \n، وreadlines() قائمة بكل الأسطر. الأولى والثالثة مناسبتان للملفات الصغيرة، أما readline() فتفيد عند قراءة سطر محدد كترويسة ثم معالجة الباقي بطريقة أخرى.

ملف سجل حجمه عدة GB: كيف تعالجه؟ ولماذا تظهر أسطر فارغة عند الطباعة؟متوسط

نستخدم for line in file لأنها تقرأ سطرًا بسطر دون تحميل الملف كله. الأسطر الفارغة سببها أن كل line يحمل \n وprint تضيف سطرًا جديدًا؛ الحل line.rstrip() أو print(line, end="").

ماذا يحدث لملف report.txt المليء بالبيانات عند تنفيذ open("report.txt", "w") فقط دون كتابة أي شيء؟فخ

يُفرَّغ الملف فورًا عند الفتح وتضيع بياناته، حتى لو لم تكتب شيئًا ولم تغلقه. للقراءة استخدم "r"، وللإضافة دون مسح "a"، ولمنع الكتابة فوق ملف موجود "x".

04المسألة العملية

المطلوب: لديك ملف سجل server.log (أدناه). اكتب برنامجًا يقرؤه سطرًا بسطر، ويحسب عدد أسطر كل مستوى (INFO وWARNING وERROR)، ويطبع أسطر ERROR مع أرقامها، ويتعامل بهدوء مع غياب الملف أو وجود أسطر فارغة.

  1. فهم المطلوب

    مدخل: ملف نصي سجلّاته بصيغة LEVEL message. مخرجات: عدّاد لكل مستوى وقائمة بأسطر الأخطاء بأرقامها، بدون انهيار إن غاب الملف.

  2. خطة الحل

    دالة تفتح الملف بـ with، وتمرّ عليه بـ enumerate، وتتخطى الأسطر الفارغة، وتحدّث dict العدّاد وقائمة الأخطاء. خارج الدالة نلتقط FileNotFoundError.

  3. الكود الكامل
  4. تفسير القرارات

    with يضمن الإغلاق، والتكرار على الملف يوفّر الذاكرة، وenumerate يعطي رقم السطر، وrstrip() يحذف \n. split() تعيد قائمة فارغة للسطر الفارغ فنتخطاه. التقاط الاستثناء خارج الدالة لأن المستدعي هو من يقرر ماذا يفعل عند غياب الملف.

  5. اختبار سريع

    شغّل البرنامج بالملف المعطى فتظهر النتيجة أعلاه. ثم أضف سطرًا فارغًا في منتصف الملف (يُتخطّى دون خطأ)، وغيّر اسم الملف لترى رسالة الخطأ بدل انهيار البرنامج.

  6. تحسين أو بديل

    للملفات الصغيرة يمكن استبدال الحلقة بـ readlines()، لكن الحلقة تبقى صالحة للملف الكبير دون تغيير. وإن كان المطلوب الأخطاء فقط فـ line.startswith("ERROR") أبسط.
