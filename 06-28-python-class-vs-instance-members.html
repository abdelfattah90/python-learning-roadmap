01الشرح

Class Attributes و Class Properties: بيانات مشتركة على مستوى الـ class

لماذا؟ بعض القيم تخص الـ class كله لا كل object على حدة: اسم المدرسة، عدد الكائنات المنشأة، نسبة الضريبة. تخزينها داخل كل object تكرار، وقد تتناقض النسخ مع الوقت.

كيف؟ الـ Class Attribute متغير يُعرَّف داخل جسم الـ class خارج أي method، ويُقرأ عبر ClassName.x أو obj.x. نسمّيه Class Property عندما نستخدمه كحالة مشتركة نغيّرها على مستوى الـ class (مثل counter يزيد عند كل __init__)؛ تغييره عبر ClassName.x = ... ينعكس على كل الكائنات. المقصود هنا بيانات على مستوى الـ class، ولا علاقة لها بـ @property.

الخطأ الأشهر: obj.school = ... لا يغيّر القيمة المشتركة؛ ينشئ instance attribute جديدًا يحجبها لهذا الـ object وحده (انظر mona في المخرجات). ولهذا السبب نكتب Student.students_count += 1 ولا نكتب self.students_count += 1.

Instance Properties: حالة كل object

لماذا؟ الـ objects من نفس الـ class تختلف في بياناتها (الاسم، الرصيد، قائمة الانتظار)، فنحتاج مخزنًا خاصًا بكل object.

كيف؟ الـ Instance Properties تُنشأ بـ self.x = ...، غالبًا داخل __init__، وتعيش داخل الـ object نفسه. عند قراءة obj.x تبحث Python في الـ object أولًا ثم في الـ class، وهذا سبب ظاهرة الحجب السابقة. الدالة vars(obj) تعرض الـ instance properties فقط.

القيد المهم: أي قيمة mutable (مثل list أو dict) يجب أن تُنشأ داخل __init__؛ وضعها كـ class attribute يجعل كل الـ objects تعدّل القائمة نفسها، كما حدث مع tracks.

@property: واجهة attribute بمنطق خلف الكواليس

لماذا؟ نريد أن يكتب المستخدم room.celsius كأنها attribute عادي، بينما نحسب القيمة أو نحمي الحالة في الخلف، دون دوال get_x() وset_x().

كيف؟ @property يحوّل method إلى قيمة تُقرأ بلا أقواس. إذا لم تضف setter تصبح القيمة read-only (مثل fahrenheit)، وإذا أضفت @celsius.setter صارت قابلة للكتابة مع تنفيذ منطقك. القيمة الفعلية تُخزَّن عادةً في اسم بشرطة سفلية مثل _celsius.

القيد: لا تكتب self.celsius = value داخل الـ setter نفسه، لأنه يستدعي الـ setter من جديد في recursion لا نهائي؛ اكتب في _celsius. التحقق برفع exception سيأتي في درس لاحق، لذلك استخدمنا هنا max() لتقييد القيمة فقط.

Class Methods و Static Methods: دوال لا تحتاج object

لماذا؟ ليست كل الدوال تعمل على حالة object محدد: بعضها ينشئ objects من مصدر آخر، أو يغيّر إعدادًا مشتركًا، أو مجرد دالة مساعدة مرتبطة بموضوع الـ class.

كيف؟ @classmethod يستقبل cls (الـ class نفسه) بدل self، فيستطيع تعديل الـ class attributes وإنشاء objects، وأشهر استخداماته الـ alternative constructor مثل from_text. أما @staticmethod فلا يستقبل self ولا cls؛ هو دالة عادية تسكن داخل الـ class للتنظيم فقط. يمكن استدعاء الاثنين مباشرة من الـ class دون إنشاء object.

القاعدة: تحتاج الحالة المشتركة أو إنشاء object؟ @classmethod. لا تحتاج شيئًا منهما؟ @staticmethod. والـ static method لا يصل إلى class attributes إلا بذكر اسم الـ class صراحةً، فإذا احتجت ذلك فاجعله classmethod.

02الملخص

  • الـ Class Attribute يُعرَّف في جسم الـ class ويُشارك بين كل الـ objects؛ استخدمه للثوابت والعدّادات والإعدادات العامة (Class Properties).
  • غيّر الحالة المشتركة عبر ClassName.x؛ الكتابة عبر obj.x = ... تنشئ instance attribute يحجب القيمة المشتركة لهذا الـ object فقط.
  • الـ Instance Properties تُنشأ بـ self.x داخل __init__ وتخص object واحدًا؛ ابحث عنها أولًا ثم في الـ class عند القراءة.
  • لا تضع list أو dict كـ class attribute إلا إذا أردت مشاركتها فعلًا؛ أنشئها داخل __init__.
  • @property يعرض method كأنه attribute: بدون setter يكون read-only، ومع @name.setter تستطيع التحكم في الكتابة (والتخزين في _name).
  • @classmethod يستقبل cls ويناسب alternative constructors والحالة المشتركة، و@staticmethod لا يستقبل شيئًا ويناسب الدوال المساعدة.

03أسئلة المقابلات

ما الفرق بين Class Attribute و Instance Attribute؟أساسي

الـ Class Attribute يُعرَّف في جسم الـ class وتتشاركه كل الـ objects، بينما الـ Instance Attribute يُنشأ بـ self.x ويخص object واحدًا. عند القراءة تبحث Python في الـ object أولًا ثم في الـ class.

متابعة: متى تختار كل نوع؟ الأول للقيم المشتركة (ثابت، counter)، والثاني للحالة التي تختلف بين الـ objects.

ما وظيفة @property ولماذا نفضّله أحيانًا على get_x()؟أساسي

يتيح قراءة قيمة محسوبة أو محمية بصيغة attribute عادية (obj.x) مع تنفيذ منطق خلفها. وبدون setter تصبح القيمة read-only، فتحافظ على الواجهة نفسها إن تغيّر التنفيذ لاحقًا.

متى نستخدم @classmethod ومتى @staticmethod؟متوسط

نستخدم @classmethod عندما نحتاج الـ class نفسه (cls) لتعديل حالة مشتركة أو إنشاء object بطريقة بديلة. ونستخدم @staticmethod للدالة المساعدة التي لا تحتاج self ولا cls، وتبقى في الـ class لأن موضوعها مرتبط به.

لماذا لا يكفي self.count += 1 لتحديث عدّاد مشترك؟متوسط

لأن القراءة تأتي من الـ class attribute، لكن الكتابة تنشئ instance attribute جديدًا في الـ object ويبقى عدّاد الـ class كما هو. الصحيح هو ClassName.count += 1، أو cls.count += 1 داخل classmethod.

في class فيه items = [] كـ class attribute، إذا أضفنا عنصرًا عبر a.items.append(1)، ماذا سيرى b.items؟فخ

سيرى [1] أيضًا. append تعدّل الـ list المشتركة نفسها ولا تعيد ربط الاسم، فلا يتكوّن instance attribute. أما a.items = [1] فيحجب القائمة المشتركة لـ a وحده. الحل: أنشئ القائمة داخل __init__.

04المسألة العملية

المسألة: أنشئ class باسم BankAccount يمثل حسابات بنك تجريبي: اسم البنك مشترك بين كل الحسابات، وعدّاد يحسب عدد الحسابات المفتوحة، ولكل حساب owner ورصيد لا يمكن تعديله من الخارج. أضف طريقة لإنشاء حساب من نص مثل "Sara:1500"، ودالة تتحقق أن المبلغ موجب.

  1. فهم المطلوب

    نصنّف كل متطلب إلى نوعه: اسم البنك والعدّاد مشتركان (Class Attributes)، وowner والرصيد خاصان بكل حساب (Instance Properties)، والرصيد read-only (@property)، والإنشاء من نص (@classmethod)، والتحقق من المبلغ (@staticmethod).

  2. خطة الحل

    نعرّف الـ attributes المشتركة في جسم الـ class، ونخزّن الرصيد في _balance داخل __init__ مع زيادة العدّاد عبر اسم الـ class، ثم نضيف property للقراءة فقط، ثم classmethod يفكّك النص ويستدعي cls، ثم staticmethod للتحقق.

  3. الكود الكامل

  4. تفسير القرارات

    كتبنا BankAccount.accounts_opened += 1 ولم نكتب self.accounts_opened += 1 حتى لا يُنشأ instance attribute يحجب العدّاد. واستخدمنا cls(...) في from_string بدل اسم الـ class ليبقى الـ constructor البديل مرتبطًا بالـ class الذي استُدعي منه. وجعلنا is_valid_amount static لأنه لا يحتاج حالة أي حساب.

  5. اختبار سريع

    المخرجات 1500.0 1 False تثبت ثلاثة أشياء: النص تحوّل إلى رصيد رقمي، والعدّاد زاد مرة واحدة، والمبلغ السالب مرفوض. وجرّب sara.balance = 0؛ ستحصل على AttributeError لأن الـ property بلا setter.

  6. تحسين أو بديل

    أضف method عادية deposit(self, amount) تستدعي BankAccount.is_valid_amount(amount) قبل تعديل _balance؛ بهذا يتغيّر الرصيد عبر منطق محكوم فقط. ويمكن لاحقًا استبدال التحقق بـ exception عندما ندرسها.
