01الشرح

Regular Expressions و Regex Patterns: وصف «شكل» النص

لماذا؟ in وstartswith() وfind() تبحث عن نص ثابت فقط، لكن كثيرًا من المشكلات تبحث عن شكل: أربعة أرقام، بريد إلكتروني، تاريخ. الـ Regular Expression (اختصارًا regex) وصف مختصر لشكل النص، والـ pattern هو النص الذي تكتب به هذا الوصف.

كيف يعمل؟ يمرّ محرك الـ regex على النص من اليسار إلى اليمين ويجرّب مطابقة الـ pattern عند كل موضع، ثم يعيد أول تطابق ناجح. لغة الأنماط متقاربة جدًا بين لغات البرمجة، فما تتعلمه هنا ينفعك خارج Python أيضًا.

أهم مكوّنات Regex Patterns:

  • حروف عادية: ERROR تطابق نفسها حرفيًا.
  • أصناف المحارف: \d رقم، \w حرف أو رقم أو _، \s مسافة بيضاء، . أي محرف عدا السطر الجديد، [A-Z] أي محرف من المجموعة، [^0-9] أي محرف خارجها.
  • المكرِّرات (quantifiers): + مرة أو أكثر، * صفر أو أكثر، ? صفر أو مرة، {4} أربع مرات بالضبط، {2,4} من اثنتين إلى أربع.
  • المراسي (anchors): ^ بداية النص، $ نهايته، \b حدّ الكلمة.
  • التجميع والاختيار: ( ) لتجميع جزء واستخراجه لاحقًا، و| بمعنى «أو».
  • الهروب (escape): \. تطابق نقطة حقيقية، بينما . وحدها تطابق أي محرف.

القيد المهم: المكرِّرات «جشعة» (greedy) افتراضيًا؛ تأخذ أطول تطابق ممكن. أضف ? بعدها (.+?) لتأخذ أقصر تطابق.

re Module و search(): البحث عن أول تطابق

re Module جزء من المكتبة القياسية، فيكفي import re دون PIP. دوال الوحدة تأخذ الـ pattern أولًا ثم النص: re.search(pattern, string).

اكتب الـ pattern دائمًا كـ raw string (r"..."). في string عادية يفسّر Python الشرطة العكسية قبل أن يراها re؛ فـ "\b" تصبح محرف backspace لا حدّ كلمة، و"\d" تعطي تحذيرًا.

search() تفحص النص كله وتعيد أول تطابق في أي موضع كـ Match object، أو None إن لم تجد شيئًا. من الـ Match object تستخرج: group() التطابق الكامل، group(1) أول مجموعة بين أقواس، span() موضع البداية والنهاية.

الخطأ الشائع: استدعاء .group() مباشرة على النتيجة؛ إن عادت None ستحصل على AttributeError. افحص النتيجة بـ if match: أولًا.

findall(): استخراج كل التطابقات

لماذا؟ search() تعطيك أول تطابق فقط. عندما تريد كل التطابقات (كل البريد في نص، كل الأرقام) استخدم findall().

كيف تعمل؟ تعيد list بكل التطابقات غير المتداخلة، وقائمة فارغة [] إن لم تجد شيئًا (لا None). وشكل العناصر يتبع الأقواس: بلا مجموعات تعيد strings للتطابق كاملًا، ومع مجموعة واحدة تعيد محتواها فقط، ومع أكثر من مجموعة تعيد tuples.

الفخ: إضافة أقواس للتجميع فقط تغيّر ما تعيده الدالة دون أن تنتبه. إن أردت التجميع بلا استخراج فاستخدم (?:...).

split() و sub(): التقسيم والاستبدال بالأنماط

split() مثل str.split() لكن الفاصل فيها pattern لا نص ثابت؛ مناسبة لنص بفواصل مختلطة وفراغات غير منتظمة، والمعامل maxsplit يحدّد عدد مرات التقسيم. تنبيه: لو وضعت الفاصل بين أقواس تُلتقط الفواصل وتظهر في النتيجة أيضًا.

sub() بصيغة re.sub(pattern, repl, string) تستبدل كل التطابقات (أو عددًا محددًا عبر count) وتعيد string جديدة. لأن الـ strings immutable فالنص الأصلي لا يتغير، وإن لم تحفظ الناتج في متغير ضاع. ويجوز أن يكون repl دالة (مثل lambda) تستقبل Match object وتعيد النص البديل.

02الملخص

  • الـ Regular Expression وصف لشكل النص، والـ pattern هو نص الوصف؛ تستخدمه حين لا يكفي البحث عن نص ثابت.
  • أهم مكوّنات الأنماط: \d و\w و\s و[...]، والمكرِّرات + * ? {n}، والمراسي ^ $ \b، والأقواس ( ) للتجميع.
  • المكرِّرات greedy افتراضيًا؛ استخدم ? بعدها (.+?) للحصول على أقصر تطابق.
  • وحدة re قياسية (import re)، وتُكتب الأنماط دائمًا كـ raw string: r"...".
  • search() تعيد أول Match object أو None، فافحصها بـ if match: قبل group()؛ وfindall() تعيد list (فارغة عند عدم التطابق) وشكل عناصرها يتبع عدد المجموعات.
  • split() تقسّم بفاصل pattern، وsub() تعيد string جديدة ولا تعدّل الأصل، ويجوز أن يكون بديلها دالة.

03أسئلة المقابلات

ما الـ Regular Expression، ومتى أفضّلها على string methods؟أساسي

هي لغة لوصف شكل النص ثم البحث عنه أو استخراجه أو استبداله. أستخدمها حين يكون المطلوب نمطًا (أرقام بصيغة معينة، بريد إلكتروني، تاريخ). أما للنص الثابت فـ in أو startswith() أبسط وأسرع في القراءة.

لماذا نكتب الـ pattern كـ raw string؟أساسي

لأن Python يعالج الشرطة العكسية في الـ string العادية قبل وصولها إلى re. فمثلًا "\b" تصبح backspace لا حدّ كلمة. الصيغة r"\b" تمرّر الشرطة كما هي إلى محرك الـ regex.

ما الفرق بين search() وfindall()؟متوسط

search() تتوقف عند أول تطابق وتعيد Match object أو None، فتفيدك حين تحتاج الموضع أو المجموعات. findall() تعيد list بكل التطابقات، وقائمة فارغة إن لم تجد شيئًا، فتناسب الاستخراج الجماعي.

ماذا تعيد findall() إذا احتوى الـ pattern على مجموعات؟متوسط

مع مجموعة واحدة تعيد قائمة بمحتوى هذه المجموعة فقط، ومع أكثر من مجموعة تعيد قائمة tuples، عنصر لكل مجموعة. إن لم أرد هذا السلوك استبدلت الأقواس بـ (?:...).

متابعة: كيف أحصل على التطابق الكامل مع وجود مجموعات؟ أستخدم search() وأقرأ group()، أو أجعل أقواس التجميع غير ملتقِطة.

ما ناتج re.findall(r"<.+>", "<b>bold</b>") ولماذا؟فخ

الناتج ['<b>bold</b>']: تطابق واحد طويل، لأن .+ جشعة وتمتد حتى آخر > في النص. للحصول على ['<b>', '</b>'] نكتب <.+?>.

متابعة: لتحليل HTML حقيقي يُفضَّل parser مخصص، فالـ regex تناسب الأنماط البسيطة فقط.

04المسألة العملية

وصلتك رسالة دعم فني واحدة كنص طويل. اكتب دالة analyze_ticket(text) تعيد dict يحتوي: كل أرقام الطلبات بصيغة ORD- ثم أربعة أرقام، وتاريخ ووقت أول ERROR، وقائمة الـ tags (الفاصل ; أو ,)، ونسخة من النص بعد إخفاء البريد الإلكتروني. إذا غابت بعض البيانات فلا يجب أن ينهار البرنامج.

  1. فهم المطلوب

    المدخل string واحدة، والمخرج dict بأربعة استخراجات: كل أرقام الطلبات (قائمة)، وأول ERROR (قيمة واحدة قد تغيب)، وقائمة tags، ونص بلا بريد إلكتروني. الحالة الحدّية: نص لا يحتوي بعض هذه البيانات.

  2. خطة الحل

    أستخدم findall() للطلبات لأنها متعددة، وsearch() للخطأ ولسطر Tags لأن كلًّا منهما يظهر مرة واحدة، ثم split() لتقسيم الـ tags، وsub() لإخفاء البريد. كل pattern يُكتب كـ raw string.

  3. الكود الكامل

  4. تفسير القرارات

    مجموعتا ERROR (\d{4}-\d{2}-\d{2}) (\d{2}:\d{2}) تعطيان التاريخ والوقت منفصلين. النمط Tags: (.+?) \| يستخدم .+? الكسولة ليتوقف عند أول |، والشرطة العمودية مهروبة لأنها تعني «أو». و\s*[;,]\s* يمتص الفراغات حول الفاصل فلا تبقى مسافات داخل الـ tags. الشرط if error else None يمنع AttributeError عند غياب التطابق.

  5. اختبار سريع

    السطر الأخير في الكود يختبر نصًا بلا بيانات: analyze_ticket("no data")؛ والمخرجات أعلاه تؤكد أنه يعيد قوائم فارغة وNone دون أي خطأ، ويبقى النص كما هو.

  6. تحسين أو بديل

    عند تكرار الأنماط نفسها على آلاف الرسائل يمكن لاحقًا تجهيزها مرة واحدة بـ re.compile()، كما تجعل المجموعات المسمّاة (?P<date>...) القراءة أوضح. وتذكّر أن pattern البريد هنا مبسّط ولا يصلح للتحقق الصارم من صحة العناوين.
