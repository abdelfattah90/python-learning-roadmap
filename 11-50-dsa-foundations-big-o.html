01الشرح

1) Introduction to DSA: لماذا نحتاج هياكل البيانات والخوارزميات؟

Data Structure هي طريقة منظّمة لتخزين البيانات (مثل list وdict وset التي عرفتها)، وAlgorithm هي خطوات محددة لحل مشكلة باستخدام هذه البيانات. نحتاجهما لأن المشكلة الواحدة قد تُحل بطريقتين: إحداهما تنتهي فورًا والأخرى تتباطأ بشدة عندما تكبر البيانات. نختار الهيكل حسب العملية الأكثر تكرارًا (بحث، إضافة، حذف، ترتيب)، ولا يوجد هيكل أفضل دائمًا؛ كل اختيار هو trade-off بين السرعة والذاكرة وبساطة الكود.

المثال يعدّ الخطوات بدل قياس الزمن: البحث عن lina احتاج 3 خطوات، والبحث عن اسم غير موجود احتاج المرور على العناصر الخمسة كلها. هذه هي فكرة التعقيد التي نصوغها رسميًا في آخر الدرس.

2) Lists and Arrays: كيف تُخزَّن العناصر وما تكلفة عملياتها؟

في DSA، الـ array عناصر متجاورة في الذاكرة، لذلك الوصول إلى أي عنصر بالـ index مباشر. الـ list في Python هي dynamic array: تكبر تلقائيًا وتحتفظ بمراجع (references) لعناصر قد تكون من أنواع مختلفة. أما array.array (من درس Python Arrays) فتخزّن قيمًا من نوع واحد بشكل مضغوط، وتناسب الكميات الكبيرة من الأرقام. تكلفة العمليات على list هي ما يهمنا هنا:

  • items[i] وappend() وpop() من النهاية: O(1) (الـ append بمتوسط amortized).
  • insert(0, x) وpop(0) وremove(x): O(n) لأن بقية العناصر تنزاح.
  • x in items والبحث عن قيمة: O(n) لأنه يفحص عنصرًا عنصرًا.

أشهر خطأ: استخدام pop(0) أو insert(0, x) داخل loop كبيرة، فتتحول عملية تبدو بسيطة إلى O(n²) دون أن تنتبه.

3) Time Complexity (Big O): قياس نمو الخطوات

تصف Big O Notation كيف ينمو عدد الخطوات عندما يكبر حجم المدخلات n، ولا تقيس الثواني لأنها تتغير حسب الجهاز والحمل. نهتم عادةً بالحالة الأسوأ (worst case) لأنها تعطي ضمانًا. أهم الأصناف:

  • O(1): ثابت، مثل items[i].
  • O(log n): يقسم المساحة إلى النصف كل خطوة، مثل binary search على list مرتبة.
  • O(n): loop واحدة، ومنها x in items.
  • O(n log n): الترتيب الجيد، مثل sorted().
  • O(n²): loops متداخلة على نفس البيانات.

لاحظ أن الفرق يصبح هائلًا عند n = 1000: نحو 10 خطوات لـ O(log n) مقابل مليون لـ O(n²).

4) قواعد حساب Big O وSpace Complexity

  • احذف الثوابت: O(2n) تصبح O(n).
  • احذف الحدود الأصغر: O(n² + n) تصبح O(n²).
  • المتتابع يُجمع والمتداخل يُضرب: loop ثم loop = O(n + n)، وloop داخل loop = O(n * n).
  • مدخلان مستقلان يحتاجان متغيرين: O(n * m) وليس O(n²).
  • Space Complexity تقيس الذاكرة الإضافية التي يستهلكها الحل، وغالبًا نشتري السرعة بذاكرة أكثر.

الخطوة الأغلى (loops المتداخلة) هي التي تحدد التعقيد الكلي، أما first = items[0] فتختفي أمامها.

02الملخص

  • Data Structure تنظّم البيانات، وAlgorithm خطوات حل المشكلة؛ واختيارهما trade-off بين السرعة والذاكرة والبساطة.
  • الـ array يعطي وصولًا مباشرًا بالـ index، وlist في Python هي dynamic array، وarray.array مخصصة لنوع واحد من القيم.
  • على list: الـ index والـ append() وpop من النهاية O(1)، بينما insert(0, x) وpop(0) وin هي O(n).
  • Big O تقيس نمو الخطوات مع n في الحالة الأسوأ، وليس الزمن بالثواني.
  • الأصناف الشائعة بالترتيب من الأسرع: O(1) ثم O(log n) ثم O(n) ثم O(n log n) ثم O(n²).
  • احذف الثوابت والحدود الأصغر، واجمع المتتابع واضرب المتداخل، واستخدم متغيرًا مستقلًا لكل مدخل.

03أسئلة المقابلات

ما هي Big O ولماذا لا نقيس سرعة الكود بالثواني؟أساسي

تصف Big O كيف ينمو عدد الخطوات (أو الذاكرة) مع زيادة حجم المدخلات n. الثواني تتأثر بالجهاز واللغة والحمل اللحظي، أما Big O فتقارن الخوارزميات نفسها وتكشف ما سيحدث عندما تكبر البيانات.

ما الفرق بين list وarray.array في Python؟أساسي

الـ list هي dynamic array تحتفظ بمراجع لعناصر من أنواع مختلفة، أما array.array فتخزّن قيمًا من نوع واحد (محدد بالـ typecode) بشكل مضغوط. الأولى أكثر مرونة والثانية أوفر في الذاكرة للأرقام.

لماذا append() تعتبر O(1) بينما insert(0, x) تعتبر O(n)؟متوسط

الـ append تضيف في النهاية دون إزاحة؛ وأحيانًا تكبّر list مساحتها وتنسخ العناصر، لكن ذلك نادر فمتوسط التكلفة (amortized) هو O(1). أما insert(0, x) فتزيح كل العناصر الموجودة خطوة واحدة في كل استدعاء.

متابعة: كيف تتجنب pop(0) داخل loop؟ اقرأ بـ index متحرك، أو اعكس الترتيب واستخدم pop() من النهاية.

ما تعقيد حلقتين متتاليتين على list حجمها n؟ وماذا لو كانتا متداخلتين على قائمتين حجماهما n وm؟متوسط

المتتاليتان: O(n + n) = O(2n) فتصبح O(n). المتداخلتان على قائمتين مختلفتين: O(n * m) وليس O(n²)، لأن الحجمين مستقلان ولا يجوز دمجهما في متغير واحد.

هذا الكود يمر على items مرة واحدة، فهل هو O(n)؟ for x in items: if x in seen_list: ...فخ

لا. الـ loop الخارجية O(n)، لكن x in seen_list على list هي نفسها O(n) وتقع داخل الـ loop، فالمجموع O(n²). استبدال seen_list بـ set يجعل الفحص O(1) بمتوسط، فيعود الكود إلى O(n).

04المسألة العملية

المسألة: لديك list من أرقام الطلبات (order IDs) وتريد اكتشاف أول رقم مكرر لمنع معالجة الطلب مرتين. اكتب حلين: الأول بحلقتين متداخلتين، والثاني بـ set. اجعل كل دالة تعيد الرقم المكرر (أو None) مع عدد الخطوات، ثم قارن النمو على 201 رقمًا.

  1. فهم المطلوب

    المدخل: list من أرقام الطلبات. المخرج: tuple من (duplicate_id أو None, steps). نعدّ الخطوات لنقارن نمو الحلين لا زمنهما على جهاز بعينه.

  2. خطة الحل

    النسخة الأولى تقارن كل زوج من العناصر (O(n²)). النسخة الثانية تحتفظ بـ set لما رأته وتفحص كل رقم جديد فيها (O(n)). ثم نشغّل الاثنتين على البيانات نفسها.

  3. الكود الكامل

    الكود التالي يضم الدالتين والاختبار.

  4. تفسير القرارات

    جعلنا j يبدأ من i + 1 لتجنب مقارنة العنصر بنفسه وتكرار الزوج، لكن العدد يبقى n(n-1)/2 أي O(n²). واخترنا عدّاد steps بدل قياس الزمن لأنه ثابت ومستقل عن الجهاز، واستخدمنا set لأن in عليها O(1) بمتوسط.

  5. اختبار سريع

    وضعنا المكرر في آخر عنصر عمدًا (الحالة الأسوأ): الحل المتداخل احتاج 20100 خطوة والحل بالـ set 201 فقط. والحالة بلا تكرار تعيد None بعد المرور على كل العناصر.

  6. تحسين أو بديل

    الـ set أسرع لكنها تكلّف O(n) ذاكرة إضافية، وتتطلب عناصر قابلة للـ hash. بديل بلا ذاكرة إضافية كبيرة: رتّب القائمة بـ sorted() (O(n log n)) ثم قارن كل عنصر بجاره.
