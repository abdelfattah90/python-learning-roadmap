01الشرح

JSON Syntax — صيغة نصية لتبادل البيانات

نحتاج JSON لأن البرامج المختلفة (واجهات API، ملفات الإعدادات، تطبيقات الموبايل) تحتاج صيغة نصية موحدة لا تعتمد على لغة بعينها. JSON هو نص وليس كائنًا في Python، وشكله قريب من dict وlist لكن قواعده أصرم.

القيم المسموحة: object {}، array []، string، number، true / false، وnull. والمفاتيح دائمًا strings بعلامات اقتباس مزدوجة. لا توجد single quotes ولا trailing commas ولا comments. أشهر خطأ: لصق dict من Python (True، None، 'x') وتوقع أنه JSON صالح.

JSON to Python Objects و json.loads()

الدالة json.loads(s) تأخذ str (الحرف s يعني string) وتحلله (parsing / deserialization) إلى كائنات Python جاهزة للاستخدام. التحويل كالتالي:

  • object ← dict، وarray ← list، وstring ← str
  • number ← int أو float (حسب وجود الكسر العشري)
  • true / false ← True / False، وnull ← None

إذا كان النص غير صالح تُرفع json.JSONDecodeError (وهي فرع من ValueError)، فلف التحليل بـ try...except عندما يأتي النص من مصدر خارجي. وبعد التحليل تتعامل مع البيانات كـ dict وlist عادية، فاستخدم .get() لتجنب KeyError عند غياب مفتاح. تنبيه: للقراءة من ملف مباشرة توجد json.load() بدون s، وهي خارج نطاق هذا الدرس.

Python Objects to JSON و json.dumps()

الدالة json.dumps(obj) تفعل العكس: تحوّل كائن Python إلى str بصيغة JSON (serialization)، وهذا ما نحتاجه عند إرسال بيانات إلى API أو حفظها كنص. الـ tuple يصبح array، وTrue يصبح true، وNone يصبح null. وأهم الوسائط: indent لتنسيق مقروء، sort_keys لترتيب ثابت للمفاتيح، وensure_ascii=False للإبقاء على الحروف العربية بدل \uXXXX.

قيد مهم: dumps تدعم الأنواع الأساسية فقط. أي نوع آخر مثل date أو set يرفع TypeError، والحل أن تحوّل القيمة بنفسك أو تمرر دالة عبر الوسيط default=.

02الملخص

  • JSON هو نص لتبادل البيانات: مفاتيحه strings بعلامات اقتباس مزدوجة، ولا يقبل comments ولا trailing commas.
  • قيم JSON هي object وarray وstring وnumber وtrue/false وnull، وتقابل في Python: dict وlist وstr وint/float وTrue/False وNone.
  • json.loads(s) تحوّل str بصيغة JSON إلى كائنات Python، وترفع JSONDecodeError عند النص غير الصالح.
  • json.dumps(obj) تحوّل كائن Python إلى str بصيغة JSON.
  • استخدم indent وsort_keys وensure_ascii=False لمخرجات مقروءة ومستقرة تحافظ على العربية.
  • التحويل ذهابًا وإيابًا ليس مطابقًا دائمًا: المفاتيح تصبح strings، والـ tuple يصبح list، والأنواع غير المدعومة تتطلب تحويلًا أو default=.

03أسئلة المقابلات

ما الفرق بين json.loads() و json.dumps()؟ أساسي

loads تأخذ str بصيغة JSON وتعيد كائن Python، وdumps تأخذ كائن Python وتعيد str بصيغة JSON. الحرف s في الاسمين يعني string، فهما يتعاملان مع نصوص في الذاكرة لا مع ملفات.

هل JSON هو نفسه dict في Python؟ أساسي

لا. JSON نص، أما dict فكائن حي في الذاكرة. وفي JSON يجب أن تكون المفاتيح strings بعلامات اقتباس مزدوجة، وتُكتب القيم true وfalse وnull بدل True وFalse وNone، ولا يُسمح بـ comments أو trailing commas.

ماذا يحدث عند تحويل date أو set بـ json.dumps()، وكيف تعالجه؟ متوسط

ترفع dumps الخطأ TypeError لأن النوع غير مدعوم في JSON. الحل الأول تحويل القيمة قبل الاستدعاء (date.isoformat() أو list(my_set))، والثاني تمرير دالة في default= تحوّل الأنواع غير المدعومة إلى قيم مدعومة.

لماذا تظهر العربية بصيغة \uXXXX بعد dumps، وكيف أمنع ذلك؟ متوسط

القيمة الافتراضية ensure_ascii=True تهرّب أي حرف غير ASCII. النتيجة JSON صالح وتعود loads بنفس النص، لكنه غير مقروء للإنسان. مرّر ensure_ascii=False للإبقاء على الحروف العربية كما هي، وindent للتنسيق.

ما نتيجة json.loads(json.dumps({1: 'a', 2: ('x', 'y')}))؟ فخ

النتيجة {'1': 'a', '2': ['x', 'y']}. المفاتيح الرقمية تصبح strings لأن مفاتيح JSON نصوص دائمًا، والـ tuple يعود list لأن JSON لا يعرف tuple. أي أن التحويل ذهابًا وإيابًا لا يعيد الكائن الأصلي دائمًا.

المتابعة: كيف تعيد المفاتيح أرقامًا؟ حوّلها بنفسك بعد التحليل، مثل {int(k): v for k, v in data.items()}.
