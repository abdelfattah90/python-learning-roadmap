Linked Lists: سلسلة من العقد

الـ list تخزّن عناصرها متجاورة، فالإدراج أو الحذف من بدايتها أو وسطها ينقل كل ما بعده (O(n)). الـ Linked List تتجنب ذلك: كل قيمة تُحفظ في Node يحمل مؤشر next إلى العقدة التالية، ولا يحتفظ الكائن إلا بـ head.

  • الإدراج: prepend يتم في O(1) لأنه يعيد ربط مؤشرين فقط.
  • الحذف: نبحث عن العقدة ثم نربط prev.next بـ cur.next فتخرج العقدة من السلسلة. حالة الحذف من head تحتاج معالجة خاصة.
  • البحث والوصول بالفهرس: O(n) لأنه لا يوجد قفز مباشر، بل مشي عقدة بعد عقدة.
  • Doubly Linked List: تضيف مؤشر prev لكل عقدة فيسهل الحذف والمشي من الطرفين.

متى تستخدمها؟ عند إدراج وحذف متكرر مع وجود مرجع للعقدة ودون وصول عشوائي. الخطأ الشائع: إعادة الربط بترتيب خاطئ فتضيع بقية السلسلة. وفي الواقع غالبًا ما تكون list المدمجة أسرع بسبب تجاور الذاكرة.

Hash Tables: من المفتاح إلى المكان مباشرة

البحث عن قيمة في list يفحص العناصر واحدًا واحدًا (O(n)). الـ Hash Table تحسب من المفتاح رقمًا عبر hash(key) ثم تحوّله إلى موضع بـ % size، فتصل إلى الـ bucket المناسب مباشرة، وهذا يعطي متوسط O(1) للإضافة والبحث.

التصادم (Collision): قد يقع مفتاحان مختلفان في الـ bucket نفسه. أشهر الحلول Chaining: كل bucket يحمل قائمة أزواج (ويمكن أن تكون Linked List)، وبعد الوصول إليه نقارن المفاتيح بـ ==. وكلما امتلأ الجدول زادت التصادمات، لذلك تُكبَّر الجداول الحقيقية وتُعاد توزيع عناصرها عند ارتفاع load factor. المثال التالي يبيّن أن put يحدّث القيمة إذا وُجد المفتاح، وأن get يعيد قيمة افتراضية إذا غاب.

Hash Tables في Python: dict وset وقيود المفاتيح

الـ dict والـ set مبنيان على Hash Table جاهز ومحسّن، فلا تكتب واحدًا بنفسك إلا للتعلم. شرط المفتاح أن يكون hashable: قيمته لا تتغير ولديه __hash__ متسق مع __eq__. لذلك تصلح str وint وtuple (إن كانت عناصرها hashable)، بينما list وdict وset تسبب TypeError، إذ لو تغيّر المفتاح لتغيّر hash وضاع العنصر في bucket خاطئ.

الاختيار: استخدم Linked List للتسلسل المرتب مع إدراج وحذف سريعين، واستخدم Hash Table (dict/set) للبحث بالمفتاح. تنبيه: قيمة hash() للنصوص تتغير بين تشغيل وآخر، فلا تعتمد عليها ولا تحفظها.

02الملخص

  • الـ Linked List سلسلة عقد، كل عقدة تحمل value وnext، ونصل لها عبر head.
  • الإدراج عند البداية O(1)، والحذف يعني إعادة ربط prev.next، والبحث O(n).
  • الـ Doubly Linked List تضيف prev لتسهيل الحذف والمشي من الطرفين، لكن list المدمجة تفوز غالبًا عمليًا.
  • الـ Hash Table تحوّل المفتاح إلى bucket عبر hash(key) % size لتعطي بحثًا متوسطه O(1).
  • التصادم حتمي، ويُعالَج بـ Chaining أو Open Addressing، وتُكبَّر الجداول عند ارتفاع load factor.
  • مفاتيح dict/set يجب أن تكون hashable (غير قابلة للتغيير)، فـ list مرفوضة وtuple مقبولة.

03أسئلة المقابلات

ما الفرق بين Linked List وlist في Python؟أساسي

الـ list مصفوفة ديناميكية تحفظ مراجع العناصر متجاورة، فالوصول بالفهرس O(1) والإدراج في الوسط O(n). أما Linked List فعقد متصلة بمؤشرات: الإدراج والحذف عند موضع معروف O(1)، لكن الوصول بالفهرس O(n).

لماذا تبقى list أسرع غالبًا؟ لأن تجاور الذاكرة وتنفيذها بلغة C يفوقان ميزة إعادة الربط.

كيف تجد Hash Table القيمة بسرعة؟أساسي

تحسب hash(key) ثم % size لتحصل على index الـ bucket، فتنتقل إليه مباشرة بدل فحص كل العناصر. لذلك يكون متوسط البحث والإضافة O(1).

ما التصادم Collision وكيف يُعالَج؟متوسط

هو وقوع مفتاحين مختلفين في الـ bucket نفسه. في Chaining يحمل الـ bucket قائمة أزواج نقارن مفاتيحها بـ ==. أما Open Addressing فيبحث عن خانة فارغة أخرى في الجدول نفسه، وهو ما يستخدمه dict في CPython.

لماذا لا يمكن استخدام list مفتاحًا في dict؟متوسط

لأنها قابلة للتغيير، فلو تغيّر محتواها تغيّر hash وأصبح مكانها في الجدول خاطئًا. لذلك ترفعها Python بـ TypeError: unhashable type، ويمكن استبدالها بـ tuple إذا كانت عناصرها hashable.

هل البحث في Hash Table دائمًا O(1)؟فخ

لا. الـ O(1) هو المتوسط فقط. إذا وقعت معظم المفاتيح في bucket واحد (دالة hash سيئة أو جدول ممتلئ) صار البحث يمر على سلسلة طويلة فيقترب من O(n) في أسوأ الحالات. وتصغير هذا الاحتمال هو سبب وجود جودة الـ hash وإعادة التوزيع.

04المسألة العملية

المسألة: لديك Linked List من العقد A -> B -> C -> D. اكتب find_cycle_start(head) التي تعيد أول عقدة تبدأ عندها حلقة (عندما يشير next لعقدة سابقة)، أو None إذا انتهت السلسلة بلا حلقة.

  1. فهم المطلوب: المدخل رأس سلسلة قد تعود إحدى عقدها لعقدة سابقة، فلا تنتهي أبدًا بـ None. المخرج هي عقدة بداية الحلقة أو None.
  2. خطة الحل: نمشي من head ونخزّن كل عقدة زرناها في set. إذا وصلنا لعقدة موجودة فيه فهي بداية الحلقة، وإذا انتهينا بـ None فلا توجد حلقة. فحص in في الـ set متوسطه O(1) (Hash Table)، فالإجمالي O(n).
