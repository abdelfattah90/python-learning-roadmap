01الشرح

Public وProtected وPrivate Members

كل class له واجهة يستخدمها الآخرون وتفاصيل داخلية يجب أن تبقى حرة التغيير. Python لا يفرض الوصول بكلمات مفتاحية، بل يعتمد على اتفاقيات تسمية:

  • Public: مثل owner بلا شرطة سفلية؛ جزء من الواجهة الرسمية.
  • Protected: مثل _branch بشرطة واحدة؛ اتفاق بأنه للـ class وأبنائه (subclasses)، ولا يمنعك Python من الوصول إليه.
  • Private: مثل __balance بشرطتين؛ يعيد Python تسميته إلى _BankAccount__balance (name mangling) لتفادي التعارض والوصول العرضي.

الخطأ الشائع: اعتبار __x حماية حقيقية. هو يمنع الوصول العرضي والتعارض في الوراثة فقط، ويمكن الوصول إليه بالاسم المعدّل.

Data Encapsulation

التغليف هو جمع البيانات والدوال التي تعالجها في class واحد، وإخفاء الحالة الداخلية خلف واجهة تتحقق من القيم. بدونه يستطيع أي كود كتابة account.balance = -999 وكسر منطق البرنامج.

الأسلوب المعتاد: attribute خاص، مع @property للقراءة، ودوال مثل deposit تعدّل الحالة بعد التحقق. استخدمه كلما وُجدت قاعدة (invariant) يجب حفظها. القيد: property بلا setter يرفع AttributeError عند الإسناد.

Nested Classes وInner Classes

Nested class هو class معرَّف داخل جسم class آخر. نستعمله لتجميع class مساعد لا معنى له إلا مع الـ outer، فلا نلوّث الـ namespace العام. ونسمّيه عادةً Inner class عندما يُنشئه الـ outer ويستخدمه داخليًا.

في Python هو ببساطة class attribute للـ outer، فنصل إليه بـ self.Battery(...) من الداخل أو Laptop.Battery(...) من الخارج. تنبيه: لا يوجد ربط تلقائي بين كائن inner وكائن outer.

Outer Class Access

الاتجاه Outer → Inner سهل عبر self.Inner أو Outer.Inner. أما Inner → Outer فلا يرى الـ inner كائن الـ outer ولا أسماءه، لأن جسم الـ class لا يكوّن scope تراه الدوال المتداخلة (كما في درس Scope). الحل: تمرير مرجع الـ outer instance صراحةً وتخزينه.

يمكن للـ inner قراءة class attributes للـ outer عبر اسم الـ outer وقت التنفيذ، مثل Course.platform. الخطأ الشائع: استخدام name داخل الـ inner مباشرة فيحدث NameError.

02الملخص

  • Python يعتمد على الاتفاقيات: Public بلا شرطة، Protected بشرطة _، Private بشرطتين __.
  • Private يخضع لـ name mangling إلى _ClassName__name؛ هدفه تفادي التعارض لا الأمان.
  • Data Encapsulation يعني إخفاء الحالة خلف واجهة تتحقق من القيم قبل تعديلها.
  • استخدم @property للقراءة المحكومة، ودوال مثل deposit للتعديل مع validation.
  • Nested/Inner class هو class attribute للـ outer، ويُستخدم لتجميع الفئات المساعدة.
  • الـ inner لا يرى كائن الـ outer تلقائيًا؛ مرّر المرجع صراحةً مثل self.Lesson(self, title).

03أسئلة المقابلات

ما الفرق بين Public وProtected وPrivate members في Python؟أساسي

Public يُكتب بلا شرطة ويمثل الواجهة المعتمدة. Protected يبدأ بـ _ وهو اتفاق على الاستخدام الداخلي وللـ subclasses، ولا يمنعه Python. Private يبدأ بـ __ ويخضع لـ name mangling فيصبح _ClassName__name، لكنه يبقى قابلًا للوصول إن عُرف الاسم المعدّل.

ما هو Data Encapsulation ولماذا نحتاجه؟أساسي

هو ربط البيانات بالدوال التي تعالجها داخل class واحد وإخفاء الحالة الداخلية خلف واجهة محكومة. فائدته حماية الـ invariants (مثل منع الرصيد السالب) وتغيير التنفيذ الداخلي دون كسر من يستخدم الـ class.

متابعة: لا تكتب setter لكل attribute؛ استخدمه فقط عند وجود validation أو قاعدة تستحق الحماية.

ما هو name mangling، وماذا يحدث لـ __x عند الوراثة؟متوسط

داخل جسم الـ class يعيد Python كتابة __x إلى _ClassName__x. فإذا عرّف الـ parent والـ child الاسم نفسه صار لكل منهما attribute مستقل ولا يطغى أحدهما على الآخر. الغرض منع التعارض غير المقصود لا إخفاء البيانات أمنيًا.

كيف يصل inner class إلى بيانات كائن الـ outer class؟متوسط

لا يوجد ربط تلقائي؛ الـ inner مجرد class attribute للـ outer. نمرّر مرجع الـ outer instance صراحةً عند الإنشاء مثل self.Lesson(self, title) ونحفظه في attribute مثل self.course، ثم يقرأ الـ inner بيانات الـ outer عبره.

ماذا يحدث عند تنفيذ account.__balance = 5 من خارج الـ class؟ هل يغيّر الرصيد الحقيقي؟فخ

لا. name mangling يُطبَّق فقط على الكود المكتوب داخل جسم الـ class، فالإسناد من الخارج ينشئ attribute جديدًا اسمه الحرفي __balance ولا يلمس _Account__balance. يعمل الكود بلا خطأ ويعطي إحساسًا زائفًا بالتعديل بينما الرصيد الحقيقي لم يتغير.
