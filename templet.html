Names and Objects - الأسماء والكائنات

لماذا؟

في Python المتغير ليس صندوقًا يحمل قيمة، بل name يشير إلى object. فهم هذا يفسّر سلوك mutable وimmutable لاحقًا.

الإسناد b = a لا ينسخ القائمة؛ هو يربط اسمًا ثانيًا بالكائن نفسه، ولذلك ظهر التعديل عند قراءة a.

Dynamic Typing - الكتابة الديناميكية

النوع يخص الكائن لا الاسم، لذلك يمكن إعادة ربط الاسم نفسه بكائن من نوع آخر.

خطأ شائع

قراءة اسم لم يُربط بعد تُنتج NameError وقت التشغيل، لا وقت الكتابة.

متى أستخدمه

أضف type hints عند الفائدة؛ لا تغيّر السلوك وقت التشغيل، لكنها تفيد المحرر وأدوات الفحص مثل mypy.

02الملخص

  • المتغير في Python اسم (name) يشير إلى كائن، وليس مساحة ذاكرة بنوع ثابت.
  • الإسناد b = a ينسخ الـ reference ولا ينسخ الكائن.
  • استخدم is لمقارنة الهوية و== لمقارنة القيمة.
  • النوع يخص الكائن، لذلك يمكن إعادة ربط الاسم بنوع مختلف.
  • قراءة اسم غير معرَّف تنتج NameError وقت التشغيل.

03أسئلة المقابلات

أساسيما الفرق بين المتغير في Python وفي C؟

في C المتغير موقع ذاكرة بنوع ثابت يخزّن القيمة. في Python المتغير اسم يشير إلى كائن، والإسناد يعيد ربط الاسم ولا ينسخ البيانات. لذلك يمكن لاسمين الإشارة إلى الكائن نفسه.

سؤال متابعة: ماذا يحدث للكائن حين لا يبقى أي اسم يشير إليه؟

متوسطما الفرق بين is و==؟

== تقارن القيم عبر __eq__، أما is فتقارن الهوية، أي هل الاسمان يشيران إلى الكائن نفسه. استخدم is مع None فقط تقريبًا.

سؤال فخهل Python pass-by-value أم pass-by-reference؟

لا هذا ولا ذاك بالمعنى الحرفي؛ يُمرَّر الـ reference إلى الكائن بالقيمة (pass by object reference). تعديل كائن mutable داخل الدالة يظهر للمستدعي، أما إعادة إسناد المعامل فلا تؤثر عليه.

سؤال متابعة: لماذا لا يتغير int الممرَّر إلى دالة تزيده بواحد؟

المسألة

نظام يبني إعدادات (config) لكل مستخدم من إعدادات افتراضية مشتركة. تعديل إعدادات مستخدم واحد يغيّر الإعدادات الافتراضية لكل المستخدمين. أصلح المشكلة.

  1. فهم المشكلة

    القاموس يحتوي قائمة tags متداخلة؛ النسخ السطحي يشارك هذه القائمة بين كل النسخ.

  2. خطة الحل

    نبني نسخة مستقلة بالكامل من الإعدادات الافتراضية عند كل استدعاء، ثم نطبّق التعديلات عليها.

  3. الكود الكامل

  4. شرح القرارات

    اخترنا deepcopy لأن copy.copy يشارك القائمة الداخلية. ولم نعدّل DEFAULTS داخل الدالة، فبقي الاستدعاء بلا آثار جانبية.

  5. اختبار سريع

    الناتج أعلاه يثبت أن DEFAULTS["tags"] بقيت ['new'] بعد تعديل نسخة المستخدم.

  6. تحسين أو بديل

    إن كانت الإعدادات ثابتة فعلًا، فاستخدم dataclass(frozen=True) مع tuple بدل list، فلا تحتاج إلى النسخ العميق.
