01الشرح

Object-Oriented Programming وClasses وObjects: الفكرة الأساسية

عندما يكبر البرنامج تتبعثر بياناته: قاموس هنا، وقائمة هناك، ودوال تعمل عليها في مكان آخر، ويصبح من السهل أن تفقد الصلة بينها. Object-Oriented Programming (OOP) أسلوب في التنظيم يجمع البيانات والدوال التي تعمل عليها داخل وحدة واحدة، فيصبح البرنامج نموذجًا لكيانات من الواقع: طالب، حساب بنكي، طلب شراء.

تقوم الفكرة على عنصرين: Class هو القالب (blueprint) الذي يصف الشكل الذي ستكون عليه البيانات والسلوك، وObject هو نسخة فعلية من هذا القالب (تسمى instance) لها بياناتها الخاصة. class واحد يمكن أن ينتج objects كثيرة مستقلة عن بعضها. وأنت تستخدم objects منذ أول الدروس: كل str وlist هي object من class مدمج في Python، وكل منها يحمل بياناته ودوالًا خاصة به.

استخدم OOP عندما يكون لديك كيان له حالة (بيانات تتغير) وسلوك (عمليات عليها)، وتحتاج إلى أكثر من نسخة منه. الخطأ الشائع هو الخلط بين المفهومين: الـ class ليس بيانات بحد ذاته، بل وصف لها، والبيانات الفعلية تعيش في الـ objects.

Create Classes وCreate Objects: التعريف ثم الإنشاء

نعرّف الـ class بالكلمة class يتبعها الاسم ثم نقطتان، والعرف في Python أن يُكتب الاسم بنمط PascalCase مثل Course. جسم الـ class يكون مزاحًا كما في الدوال، وإذا لم نرد وضع شيء بعد نستخدم pass. التعريف وحده لا ينشئ أي شيء؛ هو مجرد وصف.

لإنشاء object نستدعي الـ class كما تستدعى الدالة: Course(). كل استدعاء ينتج object جديدًا ومستقلًا، ولذلك يعطي المقارنة بـ is القيمة False حتى لو تطابق شكل الـ objects.

الخطأ المعتاد هنا هو نسيان الأقواس: Course وحدها تعني الـ class نفسه، أما Course() فتعني object جديدًا. (الاسم __main__ في المخرجات يظهر عند تشغيل الملف مباشرة كسكربت.)

Attributes: بيانات الـ object

الـ Attributes هي المتغيرات التي ترتبط بالـ object أو بالـ class. نمنح كل object بياناته الأولية عبر الدالة الخاصة __init__، وتُستدعى تلقائيًا لحظة الإنشاء. أول parameter فيها يسمى self بالعرف، وهو الـ object الذي يجري إنشاؤه الآن؛ فالسطر self.title = title يخزّن القيمة داخل هذا الـ object تحديدًا.

هناك نوعان: instance attributes مثل title وhours وهي خاصة بكل object، وclass attributes مثل platform وهي تُعرّف مرة داخل الـ class وتُشارَك بين كل الـ objects. نقرأ أي attribute ونعدّله بالنقطة: course.hours = 8.

أهم خطأ: كتابة hours = hours داخل __init__ بدل self.hours = hours؛ هذا ينشئ متغيرًا محليًا يختفي بانتهاء الدالة ولا يحفظ شيئًا في الـ object. وقراءة attribute غير موجود ترفع AttributeError.

Methods: سلوك الـ object

الـ Method هي دالة معرّفة داخل الـ class، تعمل على بيانات الـ object الذي استدعاها. أول parameter فيها هو self دائمًا؛ وPython يمرّره تلقائيًا، فالاستدعاء course.study(2) يعادل Course.study(course, 2). لذلك تستطيع الـ method قراءة attributes الـ object وتعديلها عبر self، وتبقى حالة كل object مستقلة عن غيره.

المثال يبيّن الاستقلال: بعد ساعتين وأربع ساعات من الدراسة وصل course إلى 75% بينما بقي other عند 0 لأن كل object يحمل completed الخاص به. وتفيد الـ methods في حماية قواعد الكيان: هنا min تمنع تجاوز عدد الساعات الكلي. أما نسيان self في تعريف method فيسبب TypeError عند الاستدعاء.

02الملخص

  • OOP تجمع البيانات والدوال المرتبطة بها في وحدة واحدة، فتنظّم البرنامج حول كيانات لها حالة وسلوك.
  • الـ class قالب يصف الشكل، والـ object نسخة فعلية منه (instance)؛ class واحد ينتج objects كثيرة مستقلة.
  • نعرّف الـ class بالكلمة class وبنمط PascalCase، وننشئ object باستدعائه مع الأقواس: Course().
  • الدالة __init__ تُستدعى تلقائيًا عند الإنشاء، وself هو الـ object الجاري إنشاؤه أو استدعاء الـ method عليه.
  • الـ instance attributes خاصة بكل object، أما الـ class attributes فمشتركة بين الجميع؛ وتُقرأ وتُعدَّل بالنقطة.
  • الـ method دالة داخل الـ class أول parameter فيها self، تقرأ حالة الـ object وتعدّلها دون التأثير في غيره.

03أسئلة المقابلات

ما الفرق بين الـ class والـ object؟ أساسي

الـ class وصف أو قالب يحدد attributes وmethods الكيان، ولا يحمل بيانات فعلية لأي حالة بعينها. الـ object نسخة (instance) أُنشئت من هذا القالب وتحمل بياناتها الخاصة، ويمكن إنشاء عدد غير محدود منها من class واحد.

متابعة: لماذا يعطي Course() is Course() القيمة False؟ لأن كل استدعاء ينشئ object جديدًا مستقلًا.

ما الفرق بين الـ attribute والـ method؟ أساسي

الـ attribute متغير يخزّن بيانات تخص الـ object أو الـ class، مثل title. أما الـ method فدالة معرّفة داخل الـ class تمثل سلوكًا، مثل study()، وتستطيع الوصول إلى attributes الـ object عبر self. نقرأ الأول بلا أقواس course.title، ونستدعي الثانية بأقواس course.study(2).

ماذا تفعل __init__ وما معنى self؟ متوسط

__init__ تُنفَّذ تلقائيًا بعد إنشاء الـ object مباشرة، وهي المكان المعتاد لإعطائه attributes أولية. أما self فهو مرجع إلى الـ object الحالي الذي يمرره Python كأول argument تلقائيًا؛ وبه تعرف الـ method أي object تعمل عليه. self اسم متعارف عليه وليس كلمة محجوزة، لكن تغييره يخالف الأسلوب المعتمد.

ما الذي يحدث إذا نسيت self في تعريف method ثم استدعيتها؟ متوسط

ترفع Python خطأ TypeError، لأن الاستدعاء obj.method() يمرّر الـ object تلقائيًا كأول argument، بينما التعريف لا يملك parameter لاستقباله. أي أن العدد الفعلي للـ arguments أكبر مما تتوقعه الدالة بواحد.

04المسألة العملية

أنشئ class باسم BankAccount يمثل حسابًا بنكيًا بسيطًا: يحمل اسم المالك والرصيد، وله method للإيداع وأخرى للسحب. الإيداع يقبل مبلغًا موجبًا فقط، والسحب يرفض المبلغ غير الموجب أو الأكبر من الرصيد، وكلتاهما تعيد True عند النجاح وFalse عند الرفض.

  1. فهم المطلوب

    الكيان هو الحساب: بياناته owner وbalance، وسلوكه deposit وwithdraw. كل حساب يجب أن يحتفظ برصيده الخاص، وكل عملية ترجع نتيجة نجاح أو رفض.

  2. خطة الحل

    نعرّف الـ class مع __init__ يستقبل المالك ورصيدًا افتراضيه 0، ثم method لكل عملية تتحقق من الشرط أولًا وتعدّل self.balance فقط عند الصلاحية، ثم ننشئ object ونجربه.

  4. تفسير القرارات

    الرصيد instance attribute لأن لكل حساب رصيده. والتحقق يتم في الـ method نفسها حتى لا يتجاوز أحد قواعد الحساب بتعديل الرصيد من الخارج بالخطأ. وإرجاع True أو False يسمح لمن يستدعي العملية أن يعرف هل نجحت دون أن نطبع داخل الـ class.

  5. اختبار سريع

    الناتج أعلاه يطابق المتوقع: إيداع 250 ينجح فيصبح الرصيد 750، وسحب 900 يُرفض لأنه أكبر من الرصيد فيبقى 750. وبعده يمكن أن ينجح سحب 300 فيصبح الرصيد 450، ويُرفض إيداع -5.

  6. تحسين أو بديل

    يمكن إضافة method باسم history تسجّل العمليات في قائمة تُنشأ داخل __init__ (لا كـ class attribute، تجنبًا لفخ المشاركة). كما يمكن رفع استثناء بدل إرجاع False إذا أردت تفاصيل أوضح عن سبب الرفض، وهو موضوع دروس لاحقة.
