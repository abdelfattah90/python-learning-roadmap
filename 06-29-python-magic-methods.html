01الشرح

الدوال السحرية (dunder methods) هي دوال خاصة يحيط باسمها شرطتان سفليتان مزدوجتان مثل __str__. لا نستدعيها بأنفسنا عادةً؛ Python يستدعيها عندما نستخدم صيغة معينة: print(obj) تستدعي __str__، وa + b تستدعي __add__. فائدتها أن تتصرف كائنات صنفك (class) مثل الأنواع المدمجة.

1) التمثيل النصي: __str__() و__repr__()

بدون تعريفهما تُطبع الكائنات بشكل غير مفيد مثل <Product object at 0x...>. __str__ يعطي نصًا مقروءًا للمستخدم النهائي، ويستخدمه print() وstr() وf-strings. أما __repr__ فتمثيل واضح للمطور (debugging)، ويظهر داخل القوائم وفي الـ REPL، والأفضل أن يشبه الكود الذي ينشئ الكائن.

إذا عرّفت __repr__ فقط فإن print() يستخدمه بديلًا، والعكس غير صحيح؛ لذلك ابدأ دائمًا بـ __repr__. الخطأ الشائع: استخدام print() داخل __str__ بدل return؛ فالدالة يجب أن ترجع قيمة من نوع str.

2) المقارنة والجمع: __eq__() و__lt__() و__add__()

افتراضيًا == يقارن هوية الكائن (هل هما الكائن نفسه)، فيعطي False لكائنين متطابقي القيم. عرّف __eq__ لمقارنة القيم، و__lt__ لدعم < (وهي تكفي لـ sorted() وlist.sort())، و__add__ لدعم +.

إذا كان النوع الآخر غير مدعوم فأرجع NotImplemented (لا False) ليجرّب Python الطرف الآخر ثم يرفع TypeError واضحًا. و__add__ يجب أن ترجع كائنًا جديدًا ولا تعدّل الأصل. ولا تولّد __lt__ المعاملين <= و>= تلقائيًا. فخ: تعريف __eq__ دون __hash__ يجعل Python يضبط __hash__ على None، فلا يصلح الكائن مفتاحًا في dict ولا عنصرًا في set.

3) سلوك الحاويات: __len__() و__contains__()

len(obj) تستدعي __len__ ويجب أن ترجع عددًا صحيحًا غير سالب، وx in obj تستدعي __contains__ وترجع True أو False. بهما يصبح كائنك (مثل Playlist) مألوف الاستخدام كالقوائم والمجموعات دون كشف تفاصيل تخزينه الداخلي.

إذا عرّفت __len__ فإن الكائن يُعتبر False في الشروط حين يكون طوله 0 (مثل if not playlist:)، وتستخدم not in الدالة __contains__ نفسها. الخطأ الشائع: إرجاع None أو رقم عشري من __len__ يسبب TypeError.

4) الكائن القابل للاستدعاء: __call__()

__call__ تجعل obj(...) تعمل مثل استدعاء دالة، لكن مع حالة محفوظة في attributes الكائن. تفيد عندما تحتاج «دالة» لها إعدادات (كنسبة الخصم) أو حالة تتغير بين الاستدعاءات، وهي الأساس لكتابة decorators على شكل class.

callable(obj) تعطي True عند وجود __call__. تنبيه: Discount(20) ينشئ كائنًا عبر __init__، بينما weekend_sale(500) ينفّذ __call__؛ وإذا لم تُعرَّف تظهر TypeError: object is not callable.

02الملخص

  • يستدعي Python الدوال السحرية تلقائيًا عند استخدام print() و== و+ وlen() وin وobj().
  • __str__ للعرض الموجّه للمستخدم، و__repr__ للمطور والتشخيص؛ وعند غياب __str__ يستخدم Python الـ __repr__.
  • __eq__ تقارن القيم لا الهوية، وترجع NotImplemented للأنواع غير المدعومة، وتعريفها وحدها يلغي قابلية الـ hash.
  • __lt__ تكفي لـ sorted() لكنها لا تولّد <= أو >= تلقائيًا.
  • __add__ ترجع كائنًا جديدًا، و__len__ و__contains__ تمنحان الكائن سلوك الحاويات (و__len__ تؤثر في الاختبار المنطقي).
  • __call__ تحوّل الكائن إلى callable يحتفظ بحالته بين الاستدعاءات.

03أسئلة المقابلات

ما الفرق بين __str__ و__repr__، ومتى يُستدعى كل منهما؟أساسي

__str__ يُنتج نصًا مقروءًا للمستخدم ويُستدعى من print() وstr() وf-strings. __repr__ يُنتج تمثيلًا دقيقًا للمطور ويُستدعى من repr() وعند عرض الكائن داخل قائمة. إذا غاب __str__ يستخدم Python الـ __repr__ بديلًا.

ماذا يفعل == افتراضيًا على كائنات class عادي، وكيف تغيّره؟أساسي

يقارن الهوية، أي هل الطرفان الكائن نفسه، فيعطي False لكائنين متطابقي القيم. نعرّف __eq__ ليقارن القيم، ويُفضَّل إرجاع NotImplemented إذا كان الكائن الآخر من نوع غير مناسب.

ماذا يحدث عند a + b إذا لم يعرّف a الدالة __add__؟متوسط

يحاول Python استدعاء __radd__ على b، فإن لم توجد أو أرجعت NotImplemented يرفع TypeError. لذلك ترجع __add__ القيمة NotImplemented عند نوع غير مدعوم بدل أن ترفع الخطأ بنفسها.

كيف تفرّق بين إنشاء كائن واستدعائه عند استخدام __call__؟متوسط

Discount(20) استدعاء للـ class وينشئ كائنًا عبر __init__، بينما offer(500) استدعاء للكائن نفسه وينفّذ __call__. ويمكن التحقق بـ callable(offer).

عرّفتَ __eq__ ثم وضعت كائنات الصنف في set فظهر TypeError: unhashable type. لماذا؟فخ

لأن Python يضبط __hash__ على None تلقائيًا عند تعريف __eq__ دون __hash__، فتصبح الكائنات غير قابلة للتجزئة. الحل تعريف __hash__ متسق مع __eq__ (مثل hash(self.amount))، بشرط أن تبقى القيم المستخدمة فيه ثابتة.
