01الشرح

إدارة الحزم و PyPI

بدل أن تكتب كل شيء بنفسك، تستخدم Package جاهزًا (مثل requests للتعامل مع HTTP). Package Management هو تثبيت هذه الحزم وتحديثها وحذفها وتتبّع إصداراتها، وأداتها الرسمية هي pip.

يجلب pip الحزم افتراضيًا من PyPI (Python Package Index)، وهو المستودع المركزي العام. الفرق: PyPI هو «المخزن»، وpip هو «أداة التحميل». عند التثبيت تُنسخ الحزمة إلى مجلد site-packages الخاص بالـ interpreter الذي يشغّل pip.

تنبيه: اكتب python -m pip بدل pip وحده، لتضمن أن الحزمة تُثبَّت للمفسّر نفسه الذي ستشغّل به كودك. وراجع تهجئة اسم الحزمة، فالنشر على PyPI مفتوح وقد توجد أسماء مقلَّدة خبيثة.

التثبيت والحذف وعرض الحزم

Install Packages: install يجلب أحدث إصدار متوافق مع نسخة Python لديك مع كل ما تعتمد عليه الحزمة (dependencies). تحدّد إصدارًا معيّنًا بـ == وتُرقّي بـ --upgrade. Uninstall Packages: uninstall يحذف الحزمة بعد طلب تأكيد (يتخطاه -y). List Installed Packages: list يعرض كل ما هو مثبّت بإصداراته، وshow يعرض تفاصيل حزمة واحدة (الإصدار، الموقع، وما تعتمد عليه).

قيد مهم: uninstall يحذف الحزمة المطلوبة فقط، ولا يحذف الحزم التي جُلبت معها تلقائيًا.

البيئات الافتراضية: الإنشاء والتفعيل

لو ثبّتّ كل شيء في المفسّر العام فسيتعارض مشروع يحتاج requests==2.28 مع آخر يحتاج 2.31. Virtual Environment مجلد معزول يحوي مفسّرًا وsite-packages خاصين بالمشروع، فلكل مشروع حزمه وإصداراته.

Create Environment: الأمر python -m venv .venv (وحدة venv مدمجة) ينشئ المجلد. Activate Environment: التفعيل يضع مجلد البيئة أول PATH في الطرفية، فيشير python وpip إلى البيئة ويظهر (.venv) قبل الـ prompt؛ وdeactivate يعيد الوضع السابق.

قيد مهم: البيئة غير قابلة للنقل؛ لا تنسخ مجلدها إلى جهاز آخر ولا ترفعه إلى Git، بل أعد إنشاءه من ملف الاعتماديات. وفي PowerShell قد تمنع Execution Policy سكربت التفعيل.

إدارة الاعتماديات (Manage Dependencies)

لكي يعمل مشروعك عند زميلك أو على الخادم تحتاج قائمة بالحزم وإصداراتها. الملف المعتاد هو requirements.txt: سطر لكل حزمة. pip freeze يكتب المثبّت بصيغة name==version، وinstall -r يثبّت القائمة كلها.

المحدّدات: == إصدار ثابت (أنسب لتكرار النتائج)، >= حدّ أدنى، ~=2.31 تحديثات متوافقة (تعني >=2.31, ==2.*)، والفاصلة تجمع الشروط.

تنبيه: نفّذ freeze داخل البيئة المفعّلة وإلا ستسجّل حزم المفسّر العام. وهو يسجّل أيضًا الاعتماديات غير المباشرة (transitive dependencies) وليس ما ثبّتّه بنفسك فقط.

02الملخص

  • pip هو أداة التثبيت، وPyPI هو المستودع الذي تأتي منه الحزم؛ واستخدم python -m pip لربط pip بالمفسّر الصحيح.
  • install يجلب الحزمة مع dependencies؛ ويمكن تحديد إصدار بـ == أو الترقية بـ --upgrade.
  • list وshow يكشفان ما هو مثبّت، وuninstall يحذف الحزمة المطلوبة فقط دون dependencies.
  • الـ Virtual Environment يعزل حزم كل مشروع عن غيره ويمنع تعارض الإصدارات.
  • أنشئ البيئة بـ python -m venv .venv وفعّلها حسب نظامك؛ ولا تنسخها ولا ترفعها إلى Git.
  • سجّل الاعتماديات في requirements.txt بـ pip freeze وأعد بناءها بـ pip install -r.

03أسئلة المقابلات

ما الفرق بين pip وPyPI؟أساسي

PyPI مستودع مركزي على الإنترنت يحوي آلاف الحزم، أما pip فهو أداة سطر الأوامر التي تبحث فيه وتنزّل الحزمة وتثبّتها في المفسّر. يمكن لـ pip أيضًا التثبيت من مصادر أخرى مثل ملف محلي أو مستودع Git.

لماذا نستخدم Virtual Environment لكل مشروع؟أساسي

لأن المشاريع تحتاج إصدارات مختلفة من الحزمة نفسها، والمفسّر العام لا يحمل إلا إصدارًا واحدًا منها. العزل يمنع التعارض، ويحمي حزم النظام من العبث، ويجعل قائمة اعتماديات المشروع دقيقة.

ماذا يفعل activate فعليًا؟ وهل هو ضروري؟متوسط

يضيف مجلد .venv/bin (أو Scripts في Windows) إلى بداية PATH في الطرفية الحالية فقط، فيصبح python وpip هما نسختا البيئة. ليس ضروريًا؛ يمكنك استدعاء .venv/bin/python مباشرة، وهذا شائع في السكربتات الآلية.

ما الفرق بين كتابة requirements.txt يدويًا وإنشائه بـ pip freeze؟متوسط

freeze يسجّل كل حزمة مثبّتة، بما فيها الاعتماديات غير المباشرة، بإصدارات دقيقة بـ ==، فيعطي بناءً قابلًا للتكرار لكن قائمة طويلة يصعب فهمها. الكتابة اليدوية تسجّل ما تحتاجه مباشرة بنطاقات مثل >=، فهي أوضح وأقصر لكنها أقل تكرارًا للنتائج.

بعد pip uninstall requests هل تُحذف الحزم التي ثُبّتت معها تلقائيًا؟فخ

لا. pip يحذف الحزمة المحددة فقط، فتبقى اعتمادياتها (مثل urllib3) مثبّتة وتظهر في pip list وفي freeze. للتنظيف الكامل أعد إنشاء البيئة من requirements.txt نظيف، وهذا أحد أسباب تفضيل البيئات الافتراضية.

04المسألة العملية

المسألة: فريقك يحتفظ بقائمة اعتماديات بصيغة requirements.txt، وتريد فحصها آليًا قبل التسليم. اكتب دالة audit() تتجاهل الأسطر الفارغة والتعليقات، وتبلّغ عن (1) الحزم المكررة، و(2) الحزم غير المثبّتة بإصدار دقيق ==، ثم تطبع عدد الحزم الفريدة.

  1. فهم المطلوب

    المدخل قائمة أسطر نصية، والمخرج قائمة مشاكل وعدد الحزم الفريدة. التعليق يبدأ بـ #، واسم الحزمة هو ما قبل أول محدِّد.

  2. خطة الحل

    نمرّ على الأسطر ونتخطى الفارغ والتعليق، ونقصّ السطر عند أول = أو < أو > أو ~ أو ! لنحصل على الاسم. نكشف التكرار بـ set للأسماء التي رأيناها، ونكشف غير المثبّت بغياب ==.

  3. الكود الكامل

  4. تفسير القرارات

    استخدمنا set لأن الفحص بـ in سريع ولا يهمنا الترتيب، وlist للمشاكل لنحافظ على ترتيب ظهورها. الدالة تُرجِع القيم ولا تطبع، فيسهل اختبارها وإعادة استخدامها، والطباعة تتم خارجها.

  5. اختبار سريع

    غيّر pytest إلى pytest==8.0.0 وأعد التشغيل: يختفي سطر not pinned: pytest ويبقى سطر التكرار وعدد الحزم 3.

  6. تحسين أو بديل

    المحلّل مبسّط ولا يفهم extras مثل requests[socks] ولا أسطر -r؛ للإنتاج توجد أدوات متخصصة مثل مكتبة packaging (تنبيه فقط، ليست جزءًا من هذا الدرس). وللتحقق من توافق المثبّت فعليًا استخدم python -m pip check.
