01الشرح

Lambda Functions وLambda Parameters

الـ Lambda Functions هي دوال صغيرة بلا اسم (anonymous functions) تُكتب في سطر واحد بالصيغة lambda parameters: expression، وتعيد قيمة التعبير تلقائيًا دون كلمة return. نحتاجها عندما نريد تمرير منطق قصير إلى دالة أخرى مرة واحدة، مثل مفتاح الترتيب، دون تعريف def كاملة.

أما Lambda Parameters فتعمل مثل معاملات def تمامًا: معاملات عادية، وقيم افتراضية، و*args و**kwargs. الفرق في الشكل فقط: تُكتب المعاملات بلا أقواس ولا annotations. المثال التالي يعرض الأنواع الثلاثة داخل dictionary لغرض الشرح فقط.

تنبيه: لا تخزّن lambda في متغير بالشكل square = lambda x: x * x؛ فهذا يخالف PEP 8 (القاعدة E731). إن احتجت اسمًا للدالة فاستخدم def.

Lambda Expressions

جسم lambda هو Lambda Expression واحد فقط: تعبير يُنتج قيمة، مثل عملية حسابية أو استدعاء دالة أو conditional expression بالشكل a if condition else b. السبب أن lambda صُممت لتبقى قصيرة وقابلة للقراءة داخل سطر الاستدعاء.

لا تقبل lambda أي statement: لا assignment ولا return ولا loops ولا كتل if متعددة الأسطر. إذا احتجت سطرًا ثانيًا أو شرحًا للمنطق فحوّلها إلى def. أشهر استخداماتها معامل key في sorted() وmax() وmin()، وتمرير قاعدة قصيرة إلى دالة كما في المثال:

Recursive Functions وBase Case

Recursive Functions هي دوال تستدعي نفسها لحل نسخة أصغر من المشكلة نفسها. نستخدمها عندما تكون المشكلة متداخلة أو متشابهة الأجزاء (مجلدات داخل مجلدات، قوائم داخل قوائم)، أو تُعرَّف طبيعيًا بدلالة نفسها مثل factorial.

كل دالة عودية صحيحة تحتاج جزأين: Base Case وهو الحالة الأبسط التي تعيد فيها الدالة نتيجة مباشرة دون استدعاء نفسها، وخطوة عودية تقرّب المشكلة من هذه الحالة. في المثال الشرط n <= 1 هو الـ Base Case، والاستدعاء factorial(n - 1) يقرّب القيمة منه.

أهم خطأ: نسيان الـ Base Case، أو كتابة استدعاء لا يقترب منه (مثل factorial(n) بدل factorial(n - 1)). النتيجة سلسلة استدعاءات لا تنتهي، فيوقفها Python بالخطأ RecursionError.

Recursive Calls

02الملخص

  • الـ lambda دالة مجهولة بالصيغة lambda parameters: expression، تعيد قيمة التعبير تلقائيًا دون return.
  • Lambda Parameters تدعم ما تدعمه def: القيم الافتراضية و*args و**kwargs، لكن بلا أقواس ولا annotations.
  • جسم lambda تعبير واحد فقط؛ لا statements، ويسمح بـ conditional expression، وإذا طال المنطق فاستخدم def.
  • أفضل استخدام لـ lambda هو key في sorted() وmax() وmin() والقواعد القصيرة المُمرَّرة؛ ولا تخزّنها في متغير (PEP 8).
  • الدالة العودية = Base Case + Recursive Call على مشكلة أصغر؛ وغياب الـ Base Case أو عدم الاقتراب منه يسبب RecursionError.
  • لكل Recursive Call متغيراته المحلية؛ تتراكم الاستدعاءات ثم تعود النتائج بالعكس، والعمق محدود (حوالي 1000)، فاختر loop للتكرار الخطي وrecursion للبنى المتداخلة.

03أسئلة المقابلات

ما الفرق بين lambda وdef، ومتى تفضّل كلًّا منهما؟ أساسي

كلاهما ينشئ function object. الدالة def لها اسم وتقبل عدة statements وdocstring وannotations، بينما lambda بلا اسم وجسمها تعبير واحد يُعاد تلقائيًا. نستخدم lambda لمنطق قصير يُمرَّر مرة واحدة (مثل key)، وdef لأي منطق يُعاد استخدامه أو يحتاج وضوحًا.

سؤال متابعة: لماذا يُفضَّل def على f = lambda ...؟ لأن الدالة المخزّنة تظهر في رسائل الخطأ باسم <lambda> فيصعب تتبعها.

ما هو الـ Base Case، ولماذا لا غنى عنه في الدالة العودية؟ أساسي

هو الحالة التي تعيد فيها الدالة النتيجة مباشرة دون أن تستدعي نفسها. بدونه لا تتوقف الاستدعاءات، فيرفع Python الخطأ RecursionError عند تجاوز الحد الأقصى للعمق. ويجب أن يقترب كل Recursive Call من الـ Base Case، مثل n - 1.

لماذا تفشل lambda x: return x * 2، وما الذي يمكن كتابته داخل lambda؟ متوسط

لأن جسم lambda يجب أن يكون expression، بينما return هو statement. المسموح: عمليات حسابية واستدعاء دوال وtuples وconditional expression مثل a if condition else b. الممنوع: assignment وloops وكتل if متعددة الأسطر.

كيف تعمل Recursive Calls خطوة بخطوة، ومتى تفضّل loop عليها؟ متوسط

كل استدعاء ينتظر نتيجة الاستدعاء الأعمق حتى الوصول إلى الـ Base Case، ثم تعود القيم بالترتيب العكسي كما في trace الدالة sum_list. نفضّل loop للتكرار الخطي البسيط لأنه أسرع ولا يتأثر بحد العمق (حوالي 1000)، ونستخدم recursion للبنى المتداخلة مثل المجلدات.

04المسألة العملية

لديك شجرة مجلدات مشروع، وكل مجلد tuple بالشكل (name, size_mb, children) حيث children قائمة بالمجلدات الفرعية. اكتب دالة عودية total_size تحسب الحجم الكلي لمجلد مع كل ما بداخله، ثم رتّب المجلدات الفرعية للمشروع من الأكبر إلى الأصغر باستخدام lambda، واطبع الحجم الكلي للمشروع.

  1. فهم المطلوب

    المدخل شجرة tuples بعمق غير معروف، والمخرجات: الحجم الكلي لكل مجلد فرعي مرتبًا تنازليًا، ثم الحجم الكلي للمشروع. تداخل المجلدات داخل بعضها يجعل المشكلة مناسبة للـ recursion.

  2. خطة الحل

    الـ Base Case: مجلد بلا children يعيد حجمه فقط. الخطوة العودية: حجم المجلد مضافًا إليه total_size لكل مجلد فرعي. للترتيب نستخدم sorted() مع lambda تعيد (-size, name).

  4. تفسير القرارات

    فككنا الـ tuple بـ _, size, children = folder لأن الاسم غير مطلوب داخل الحساب. استخدمنا -total_size(f) بدل reverse=True كي يبقى كسر التعادل بالاسم تصاعديًا. واخترنا lambda لأن مفتاح الترتيب يُستخدم مرة واحدة فقط. الـ Base Case هنا صريح للتوضيح، والحلقة نفسها تتوقف طبيعيًا عند قائمة children فارغة.

  5. اختبار سريع

    تحقق يدويًا: 4 + 235 + 60 + 300 = 599 وهو ناتج total:. جرّب أيضًا total_size(("empty", 7, [])) فيعيد 7 مباشرة من الـ Base Case، ثم أضف مجلدًا داخل docs وتأكد أن الإجمالي يزيد بحجمه.
