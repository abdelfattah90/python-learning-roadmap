01الشرح

Trees و Binary Trees: بنية هرمية بدل الخطية

القوائم والـ arrays خطية، لكن بيانات مثل المجلدات وتصنيفات المنتجات وشجرة DOM هرمية بطبيعتها. الـ Tree مجموعة nodes مرتبطة بحواف دون دورات، لها root واحد؛ كل node غير الجذر له parent واحد، والعقدة بلا أبناء تسمى leaf. الـ depth هو عدد الحواف من الجذر إلى العقدة، وheight هو أطول مسار نزولًا.

في الـ Binary Tree لكل node على الأكثر ابنان: left وright. نزورها بالـ recursion بثلاثة ترتيبات تختلف بموضع معالجة node: preorder (node ثم left ثم right)، وinorder (left ثم node ثم right)، وpostorder (الأبناء أولًا). وهناك level-order يمر مستوى بعد مستوى باستخدام queue من درس Stacks & Queues.

انتبه: لا تنسَ base case (node is None)، وتذكّر أن Python لها حد recursion (نحو 1000 افتراضيًا) فلا تناسب الشجرة المنحرفة العميقة جدًا.

Binary Search Trees: ترتيب يسمح بالبحث السريع

الـ BST هي binary tree بشرط: كل key في الـ subtree الأيسر أصغر من key الـ node، وكل key في الأيمن أكبر منه (الشرط على الـ subtree كله لا على الابن المباشر فقط). عند البحث أو الإدخال نقارن ثم ننزل يسارًا أو يمينًا فنتجاهل جزءًا كبيرًا من الشجرة كما في binary search، والتكلفة O(h) حيث h ارتفاع الشجرة. وزيارة inorder تُخرج المفاتيح مرتبة تصاعديًا.

الحذف أصعب: leaf يُحذف مباشرة، وnode بابن واحد يُستبدل بابنه، وnode بابنين يُستبدل بـ inorder successor (أصغر key في الـ subtree الأيمن). الخطأ الأشهر: إدخال بيانات مرتبة (1, 2, 3, ...) يجعل الشجرة سلسلة بارتفاع n فتصبح العمليات O(n) مثل linked list.

AVL Trees: BST تحافظ على توازنها

لمنع الانحراف، الـ AVL Tree هي BST تفرض أن balance factor = height(left) - height(right) يبقى -1 أو 0 أو 1 عند كل node. بعد كل insert أو delete نصعد من الأسفل ونحدّث الارتفاعات، وإذا خرج balance factor عن المدى نصلحه بـ rotation: حالة Left-Left تُحل بـ right rotation، وRight-Right بـ left rotation، وLeft-Right بـ left rotation على الابن ثم right rotation على node، وRight-Left بالعكس.

المثال يعرض الدوران فقط؛ في AVL كاملة نحدّث حقل height للعقدتين بعد الدوران. النتيجة: ارتفاع O(log n) مضمون، فالبحث والإدخال والحذف O(log n) حتى مع بيانات مرتبة. الثمن: حقل height في كل node وكود أعقد وتكلفة rebalance عند الكتابة، لذلك تناسب الأنظمة كثيرة القراءة.

02الملخص

  • الـ Tree بنية هرمية: root وparent/child وleaf، والـ height هو أطول مسار نزولًا.
  • الـ Binary Tree لكل node فيها ابنان على الأكثر؛ preorder وinorder وpostorder تختلف بموضع معالجة node، وlevel-order يستخدم queue.
  • شرط الـ BST يخص الـ subtree كله؛ البحث والإدخال O(h)، وinorder يعطي المفاتيح مرتبة.
  • أسوأ حالة في BST هي إدخال بيانات مرتبة: h = n فتصبح العمليات O(n).
  • الـ AVL تُبقي balance factor بين -1 و1 وتصلح الخلل بأربع حالات rotation: LL وRR وLR وRL.
  • AVL تضمن O(log n) مقابل تكلفة إضافية عند الكتابة؛ والتحقق من BST يحتاج نطاق (low, high) لا مقارنة الأب فقط.

03أسئلة المقابلات

ما الفرق بين Binary Tree وBinary Search Tree؟أساسي

الـ Binary Tree شكل فقط: لكل node ابنان على الأكثر دون أي شرط على القيم. أما الـ BST فهي binary tree مع شرط ترتيب: كل key في الأيسر أصغر وفي الأيمن أكبر، لذلك تدعم بحثًا سريعًا. كل BST هي binary tree وليس العكس.

ما الفرق بين preorder وinorder وpostorder، ومتى تفيد inorder؟أساسي

الفرق في موضع معالجة node نسبةً إلى ابنيه: قبلهما (preorder)، بينهما (inorder)، بعدهما (postorder). الـ inorder على BST تُخرج المفاتيح مرتبة تصاعديًا؛ والـ postorder مناسبة عندما نحتاج نتائج الأبناء أولًا مثل حساب الارتفاع أو حذف الشجرة.

لماذا قد يصبح البحث في BST بطيئًا O(n)، وكيف يعالج AVL ذلك؟متوسط

لأن التكلفة O(h)، وإدخال بيانات مرتبة يبني سلسلة بارتفاع n. الـ AVL تعيد التوازن بـ rotations بعد كل تعديل فيبقى الارتفاع O(log n).

متابعة: ما الثمن؟ حقل height إضافي لكل node وتكلفة rotations عند insert وdelete.

ما هو balance factor، وماذا نفعل في حالة Left-Right؟متوسط

هو height(left) - height(right) ويجب أن يبقى بين -1 و1. في Left-Right يكون الثقل في الابن الأيمن للابن الأيسر؛ نعمل left rotation على الابن الأيسر فيتحول إلى Left-Left، ثم right rotation على node.

هل يكفي فحص left.key < node.key < right.key عند كل node للحكم أن الشجرة BST صالحة؟فخ

لا، لأن الشرط يخص الـ subtree كله. في شجرة جذرها 10 وابنها الأيسر 5 وله ابن أيمن 15، كل node يجتاز فحص أبنائه المباشرين، لكن 15 يقع في يسار 10 وهو أكبر منه فالشجرة غير صالحة. الحل: تمرير نطاق (low, high) أو التأكد أن inorder تصاعدي صارم.
